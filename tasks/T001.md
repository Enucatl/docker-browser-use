# T001 — Python project scaffold (uv, src layout, tooling)

## Goal

Bootstrap this repository as a proper Python package so later tasks can add FastAPI, Browser Use, and audit code without re-litigating layout.

## Context

Repo is currently a stub (`README.md`, `LICENSE`). Homelab Python stacks use `uv`, `pyproject.toml`, and a `src/` layout. Follow the Python packaging conventions used across this homelab (uv, `src/`, Google-style docstrings, type hints, pytest, ruff).

## Dependencies

- None

## In scope

1. Initialize `pyproject.toml` with package name (e.g. `browser_use_agent` or `browser_agent`), Python version pin, and build backend `uv_build` for pure Python.
2. Create `src/<package>/` with `__init__.py` and a tiny public version constant.
3. Add tool config: `ruff` (format + lint), `pytest`, and typing as appropriate.
4. Add minimal tests under `tests/` that import the package.
5. Update `.gitignore` for `.venv/`, `__pycache__/`, `.env`, `secrets/`, artifacts, coverage, etc. (keep existing useful ignores).
6. Refresh `README.md` with: purpose one-liner, `uv sync`, `uv run pytest`, pointer to `task_ledger.md`.
7. Lock deps with `uv lock` after defining dependencies needed for *scaffold only* (dev tools). Defer Browser Use / FastAPI pins to the tasks that need them, or add empty optional dependency groups if that keeps later tasks cleaner.

## Out of scope

- Docker / compose
- Application features
- Committing secrets

## Acceptance criteria

- [ ] `uv sync` succeeds
- [ ] `uv run ruff format .` and `uv run ruff check .` succeed (or project-equivalent)
- [ ] `uv run pytest` passes at least one import/smoke test
- [ ] Package is importable from `src/` layout
- [ ] No application business logic beyond scaffolding

## Suggested files

```text
pyproject.toml
uv.lock
src/<package>/__init__.py
tests/test_import.py
README.md
.gitignore
```

## Implementation notes for the model

- Prefer dependency groups (`[dependency-groups] dev = [...]`) over `requirements.txt`.
- Do not invent a monorepo; keep one package.
- Keep the public package name stable; later tasks will import it heavily.
