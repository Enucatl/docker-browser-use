# T003 — PostgreSQL service, secrets, and app DB wiring

## Goal

Add a hardened Postgres 18 database to the stack and wire the controller to it via Docker secrets, matching sibling homelab conventions.

## Context

- Baseline Postgres profile: `extends` service `postgres` from `../compose-security-baseline/hardening.yml`
- Image convention: `postgres:18`
- Data mount: `/var/lib/postgresql` (PG 18 layout)
- Password: `POSTGRES_PASSWORD_FILE=/run/secrets/postgres_password`
- DB stays on **internal** network only — never `traefik_proxy`
- References: send-bills `db` service; paperless-ai for multi-service internal networking

## Dependencies

- T002

## In scope

1. Add `db` service with healthcheck (inherited/compatible with baseline), named volume `pgdata`, internal network only.
2. Create compose `secrets:` entry for `postgres_password` from `./secrets/postgres_password`.
3. Wire controller env: host `db`, database/user names, `DATABASE_PASSWORD_FILE` (or project-consistent names).
4. Add `.env.example` DB-related non-secret vars.
5. Ensure controller `depends_on: db: condition: service_healthy`.
6. Document how to generate the secret file locally (e.g. `openssl rand -hex 32`) without committing it.
7. Optional: tiny SQL init or migration placeholder directory if useful for T006 (do not invent the full audit schema here).

## Out of scope

- Full event-sourcing schema (T006)
- Application repositories / ORM models beyond connection config
- Exposing Postgres ports to the host or Traefik

## Acceptance criteria

- [ ] `db` uses baseline `postgres` extend + `postgres:18`
- [ ] Password only via Docker secret file
- [ ] `db` not on `traefik_proxy`
- [ ] Controller can be configured to reach DB (even if app only does a connectivity check)
- [ ] `secrets/postgres_password` is gitignored

## Suggested files

```text
docker-compose.yml   # update
.env.example         # update
secrets/postgres_password   # local only, not committed
```

## Implementation notes for the model

- Prefer dedicated DB user/database (`browser_use` / similar) rather than superuser for the app.
- Keep timezone `Europe/Zurich` consistent with siblings if setting Postgres env.
