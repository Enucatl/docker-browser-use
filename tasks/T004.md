# T004 — Chromium/browser worker image and hardened runtime profile

## Goal

Define how Chrome/Chromium runs inside Docker for Browser Use: image, volumes, shared memory, display stubs, and the least-privilege posture that still allows a real browser to start.

## Context

Browser automation often cannot run under full `hardened-*` (`read_only: true`, `cap_drop: ALL`) without careful exceptions. Sibling pattern: prefer `hardened-*` first; if impossible, use `limits-*` from the same baseline and document why.

Chrome needs:

- Persistent profile volume (agent profile, not the operator’s desktop profile)
- Adequate `/dev/shm` or equivalent
- Writable paths for profile, crashes, downloads
- Later: Xvfb for headed/VNC (T022); CDP stays internal

Controller may launch browser in-process or as a sibling service; prefer a **separate `browser` (or `agent-browser`) service** on the internal network so Traefik never sees CDP.

## Dependencies

- T002

## In scope

1. Add Dockerfile stage or dedicated image with Chromium/Chrome + dependencies required by Browser Use / CDP.
2. Compose service for the browser worker:
   - Internal network only
   - Volume for Chrome profile (e.g. `chrome_profile`)
   - Volume or path for downloads/artifacts mount shared with controller if needed
   - `shm_size` or tmpfs sized for Chrome
   - Resource profile: start from `limits-xlarge` or `hardened-xlarge` with documented overrides (`read_only: false` only if proven necessary)
3. Document env for CDP endpoint binding to **internal** interface only (not `0.0.0.0` published to host).
4. Smoke command or health approach that verifies Chromium can launch headless/headed in the container (minimal).
5. Note future Bitwarden extension lives in the profile volume (T026) — do not install yet unless trivial.

## Out of scope

- Browser Use session manager code (T013)
- noVNC (T022)
- Bitwarden (T026)
- Publishing browser ports via Traefik

## Acceptance criteria

- [ ] Browser service is not on `traefik_proxy`
- [ ] Persistent profile volume defined
- [ ] Hardening choice documented in comments or README section (why `limits-*` vs `hardened-*`)
- [ ] Container can start Chromium enough to prove the image works
- [ ] CDP is not host-published

## Implementation notes for the model

- Do not expose port 9222 on the public network.
- Prefer one dedicated agent profile path; multi-profile is T031.
- Keep user namespace remapping / non-root in mind; match uid used for the profile volume.
