# T006 — Event-sourcing schema and migrations

## Goal

Create the PostgreSQL schema for immutable audit events plus normalized helper tables, with a migration tool the controller can run on startup or via a one-shot command.

## Context

Canonical timeline is `agent_events`. Normalized tables support analysis without replacing the event stream.

Logical event kinds (non-exhaustive): task received, page opened, tab created, browser state captured, Jev request/response, decision, click requested/completed, model request/response, approval requested/granted/denied, error, completion, pause/resume, takeover start/end.

Every event should support: `run_id`, `step_id` (nullable), sequence number, timestamp, actor, parent event id, URL/tab where relevant, duration, metadata.

## Dependencies

- T003

## In scope

1. Choose a migration approach (Alembic recommended with SQLAlchemy, or plain SQL migrations — pick one and stick to it).
2. Create tables at minimum:
   - `runs`
   - `agent_events` (immutable append-only)
   - `agent_decisions`
   - `model_calls`
   - `browser_actions`
   - `page_visits`
   - `human_approvals`
   - `cost_entries`
   - `errors`
   - `artifacts` (metadata only; blobs in T007)
3. Indexes for `run_id`, time range, event type, and hash-chain lookup fields (hash columns may be filled in T009).
4. Document that rows in `agent_events` are never updated/deleted in normal operation.
5. Unit/integration test that applies migrations against Postgres (compose or pytest fixture).

## Out of scope

- Hash chaining logic (T009)
- Artifact binary storage (T007)
- Writing events from the control loop (T015)

## Acceptance criteria

- [ ] Migrations apply cleanly to empty Postgres 18
- [ ] `agent_events` is clearly append-only by convention (DB grants / no update triggers optional but nice)
- [ ] Normalized tables exist with FKs to `runs` / events as appropriate
- [ ] Tests cover migrate-up at least once

## Suggested files

```text
src/<package>/db/
alembic/ or migrations/
tests/test_schema_migrate.py
```

## Implementation notes for the model

- Prefer UUID `run_id`s.
- Use `timestamptz`.
- Keep JSONB for searchable metadata; large blobs belong in artifact storage (T007/T018).
- Postgres TOAST/LZ4 is fine for ordinary JSONB; do not invent custom compression in this task.
