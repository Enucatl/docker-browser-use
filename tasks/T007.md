# T007 — Artifact store (filesystem, SHA-256 dedupe, Zstd payloads)

## Goal

Implement storage for large audit payloads and files: screenshots, compressed browser state, downloads, optional HAR — with content-addressed deduplication.

## Context

Postgres stores metadata (`artifacts` table from T006). Blobs live on a persistent Docker volume (filesystem first; MinIO is T034).

Dedup: SHA-256 of content; identical payloads stored once and referenced many times.

Compression: JSON/MessagePack + Zstd for large structured state. Images: WebP/JPEG policy is T019; this task should accept bytes + content type and store them.

## Dependencies

- T003 (volume/path available); ideally T006 for `artifacts` metadata rows

## In scope

1. Define on-disk layout under a mounted volume (e.g. `/var/lib/browser-use/artifacts/ab/cd/<sha256>`).
2. API: `put(bytes, media_type, kind) -> artifact_id/storage_key`, `get`, `exists`.
3. Compute SHA-256; skip rewrite if object exists.
4. Zstd helpers for structured payloads (encode/decode).
5. Wire compose volume `artifacts_data` (name flexible) mounted read-write on controller (and browser if downloads land there).
6. Record metadata rows when T006 is present (size, hash, media type, created_at, kind).
7. Tests with temp directories: dedupe, round-trip Zstd, missing key errors.

## Out of scope

- Screenshot capture policy (T019)
- MinIO (T034)
- Serving artifacts publicly without auth

## Acceptance criteria

- [ ] Identical bytes produce one stored object and reusable metadata references
- [ ] Zstd round-trip tested
- [ ] Compose volume defined and documented
- [ ] No secrets intentionally stored; redaction remains caller’s job (T008)

## Suggested files

```text
src/<package>/artifacts/store.py
tests/test_artifact_store.py
docker-compose.yml  # volume mount
```

## Implementation notes for the model

- Never expose the raw artifacts directory via Traefik.
- Prefer streaming hashes for large files if practical.
