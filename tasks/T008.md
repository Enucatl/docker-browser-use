# T008 — Secret redaction before any audit write

## Goal

Build a single redaction layer that strips secrets before events, model traces, or artifacts are persisted or sent to Jev/text-LLM prompts.

## Context

Trace *that* Bitwarden filled a field and whether it succeeded; never store passwords, CVVs, full PANs, session cookies, API tokens, Bitwarden vault material, or raw Authorization headers.

Redaction must happen **before** data reaches the event system (T009) and before prompt assembly for models.

## Dependencies

- T001

## In scope

1. Define a redaction module with explicit allow/deny field paths and regex heuristics for common secret shapes (password fields, `cookie`, `authorization`, `set-cookie`, JWTs, etc.).
2. Provide `redact_mapping`, `redact_text`, and browser-state redaction helpers that preserve structure but replace secret values with stable placeholders (e.g. `[REDACTED]`, masked PAN `****4242` only when last-4 is intentionally allowed).
3. Unit tests including: password-like strings, cookies, card numbers, nested DOM attribute bags, and “do not over-redact ordinary UI text” cases.
4. Document the rule: if unsure, redact.

## Out of scope

- Bitwarden actions (T027)
- Full audit writer (T009) — but export a clear interface the writer must call
- Cryptography / vault unlock flows

## Acceptance criteria

- [ ] Central redaction API used as the only approved path into audit sinks
- [ ] Tests prove known secret samples do not survive redaction
- [ ] Harmless identifiers (URL path, element role, last-4 when explicitly passed as already-masked) can remain

## Suggested files

```text
src/<package>/security/redaction.py
tests/test_redaction.py
```

## Implementation notes for the model

- Keep this dependency-light and synchronous.
- Avoid logging unredacted data “just for debug” in this module.
