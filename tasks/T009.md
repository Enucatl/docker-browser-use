# T009 — Audit event writer with hash chaining

## Goal

Implement the append-only event writer that persists redacted events, maintains per-run sequence numbers, and hash-chains events for tamper evidence.

## Context

Each event hash incorporates the previous event hash and canonicalized event contents. Periodic signed checkpoints are T035; this task only needs in-run hash chaining + verification helper.

All writes must call T008 redaction first.

## Dependencies

- T006, T008

## In scope

1. `AuditWriter.append(run_id, event_type, payload, ...)` that:
   - redacts payload
   - assigns monotonic `seq` per run
   - computes `event_hash` from canonical JSON + `prev_hash`
   - inserts into `agent_events` (and optionally fans out to normalized tables when type-specific)
2. Canonicalization rules documented (key sort, UTC timestamps, omit volatile fields).
3. `verify_run_chain(run_id) -> bool` for tests/ops.
4. Concurrency: safe under concurrent writers for different runs; for same run, serialize via transaction/`SELECT FOR UPDATE` on run row or advisory lock.
5. Tests for chain integrity and detection of tampering (mutate row → verify fails).

## Out of scope

- External signing / HSM (T035)
- OpenTelemetry (T030)
- UI for browsing events (T024)

## Acceptance criteria

- [ ] Events are immutable inserts only
- [ ] Hash chain verifies on happy path
- [ ] Tampered content fails verification
- [ ] Redaction is invoked on every append

## Suggested files

```text
src/<package>/audit/writer.py
src/<package>/audit/hashchain.py
tests/test_audit_hashchain.py
```

## Implementation notes for the model

- Use a stable hash algorithm (SHA-256).
- Store both `prev_hash` and `event_hash` on each row.
- Actor field should distinguish `agent`, `human`, `system`.
