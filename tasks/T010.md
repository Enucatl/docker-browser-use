# T010 — Agent controller FastAPI: run lifecycle API

## Goal

Stand up the always-on Agent Controller as a FastAPI app owning run CRUD/lifecycle endpoints (create, get, list, basic state transitions stubs).

## Context

Controller owns: tasks, run IDs, profiles (stub OK), approvals (stub), concurrency limits, retries, cancellation, audit events, and later the Browser Use ↔ Jev bridge.

Stack choice from plan: lightweight FastAPI (+ WebSockets in T011).

HTTP client convention in this homelab: prefer `niquests` if an HTTP client is needed.

## Dependencies

- T003, T006

## In scope

1. FastAPI app entrypoint runnable via uvicorn in Docker.
2. REST endpoints (JSON) roughly:
   - `POST /api/runs` — create run from natural-language goal + optional profile id
   - `GET /api/runs` — list recent
   - `GET /api/runs/{run_id}` — status, timestamps, goal, cost placeholder
   - `POST /api/runs/{run_id}/stop` (wire real cancel in T020; stub OK)
3. Persist `runs` rows; emit `task_received` / `run_created` via AuditWriter if T009 is available, else TODO hook.
4. Health: `GET /healthz` (unauthenticated OK for Docker healthcheck; do not put sensitive data there).
5. Config via env + `*_FILE` secrets pattern.
6. Basic pytest API tests with httpx/ASGI or similar **only if already consistent**; prefer FastAPI `TestClient`.

## Out of scope

- WebSockets (T011)
- Authelia identity enforcement (T012)
- Actual browser loop (T015)
- Full UI (T024)

## Acceptance criteria

- [ ] Container/command can serve API
- [ ] Creating a run yields a `run_id` stored in Postgres
- [ ] Healthcheck endpoint exists
- [ ] No CDP ports exposed

## Suggested files

```text
src/<package>/api/app.py
src/<package>/api/routes/runs.py
src/<package>/config.py
tests/test_runs_api.py
```

## Implementation notes for the model

- Keep routers thin; put domain logic in services.
- Design run status enum early: `queued|running|paused|awaiting_approval|awaiting_human|succeeded|failed|cancelled`.
