# T011 — WebSocket run progress and live event stream

## Goal

Stream live run progress to the Web UI over WebSockets (or SSE if strongly justified — prefer WebSockets per plan).

## Context

UI needs: current decision, step updates, approvals pending, errors, cost ticks, pause state — without polling-only UX.

## Dependencies

- T010

## In scope

1. `WS /api/runs/{run_id}/events` (path flexible) that:
   - accepts connection
   - optionally replays recent events from Postgres
   - pushes new audit/progress messages as they occur
2. In-process pub/sub or DB LISTEN/NOTIFY bridging AuditWriter → sockets.
3. Auth gate compatible with T012 (at least reject anonymous once T012 lands; temporary shared cookie/header stub documented if sequencing requires).
4. Client message schema documented (JSON types).
5. Tests with FastAPI websocket test client for subscribe + receive after an appended event.

## Out of scope

- Full UI rendering (T024)
- VNC streaming (T022)

## Acceptance criteria

- [ ] Client receives events shortly after audit append for that run
- [ ] Reconnect/replay strategy documented
- [ ] No raw secrets in WS payloads (redacted events only)

## Suggested files

```text
src/<package>/api/ws.py
src/<package>/api/events_bus.py
tests/test_ws_events.py
```

## Implementation notes for the model

- Bound payload sizes; point to artifact ids for large state instead of inlining DOM dumps.
