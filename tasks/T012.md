# T012 — Authelia `Remote-User` trust and CSRF/origin hardening

## Goal

Trust Authelia forward-auth identity headers on the controller and lock down browser-facing CSRF/origin checks for the private UI/API.

## Context

Authelia middleware sets `Remote-User`, `Remote-Groups`, `Remote-Name`, `Remote-Email` (see `/opt/docker/authelia/docker-compose.yml`).

Reference app middleware: `/opt/docker/send-bills/src/send_bills/project/middleware.py`.

Compose already should use `middlewares=authelia@docker,secured@file` (T002). This task is **application** trust of those headers — only when requests come via Traefik, never treat spoofable headers as gospel from the public internet without the proxy.

Wildcard Authelia rule for `*.docker.home.arpa` + `group:admins` likely already allows access; only edit Authelia config if a dedicated group/policy is required.

## Dependencies

- T010, T002

## In scope

1. Middleware/dependency that reads `Remote-User` (and groups) and attaches a `User` to the request.
2. Reject API/WS requests missing identity **when** `AUTH_REQUIRED=true` (default in prod).
3. Configure allowed hosts / CSRF trusted origins using `https://browser-use.${DOCKER_DOMAIN}`.
4. Document local-dev bypass (`AUTH_REQUIRED=false`) clearly — never enable in compose prod env example.
5. Tests for missing header vs present header.

## Out of scope

- OIDC client registration (not needed for forward-auth)
- Changing Authelia unless custom policy is necessary (justify in PR/notes)

## Acceptance criteria

- [x] Prod config requires Authelia identity for API (except `/healthz`)
- [x] Origins/hosts match Traefik hostname pattern
- [x] Spoofing story documented (headers only trusted behind Traefik network path)
