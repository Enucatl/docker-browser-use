# T013 — Browser Use session manager (on-demand Chrome, persistent profile)

## Goal

Integrate Browser Use so the controller can start/stop a Chrome session on demand against the persistent agent profile, with CDP remaining internal.

## Context

Chrome need not run 24/7; the controller stays up and launches Chrome when a run needs it. Profile lives on the Docker volume from T004.

Use Browser Use’s Chrome/CDP architecture (tabs/frames, screenshots, downloads, watchdogs, state history, retries). Do not attempt Firefox support.

## Dependencies

- T004, T010

## In scope

1. Add Browser Use (and needed browser deps) to project dependencies.
2. `BrowserSessionManager`:
   - ensure Chrome up for profile X
   - create/attach Browser Use browser/context for a run
   - graceful shutdown / idle TTL
   - concurrency policy (start with single active interactive session if simpler)
3. Persist profile path configuration via env.
4. Emit audit events for browser started/stopped if AuditWriter available.
5. Integration smoke test or documented manual compose test: open `about:blank`, observe state once.

## Out of scope

- Jev decisions (T014/T015)
- noVNC (T022)
- Bitwarden (T026)
- Multi-profile UX (T031) — single profile is enough

## Acceptance criteria

- [ ] Run can obtain a Browser Use-connected Chrome using the persistent profile volume
- [ ] Restarting the browser container keeps cookies/profile data on the volume
- [ ] CDP not published on Traefik/`traefik_proxy`
- [ ] Idle/shutdown path does not corrupt the profile

## Suggested files

```text
src/<package>/browser/session.py
src/<package>/browser/profiles.py
tests/test_browser_session.py  # may be marked integration/slow
```
