# T015 — Observe → Jev → execute control loop with audit hooks

## Goal

Implement the core run worker that repeatedly observes browser state, asks Jev for one action, executes it via Browser Use, and writes full audit breadcrumbs.

## Context

This is the heart of Phase 1. Everything else (approvals, Bitwarden, UI) hangs off this loop.

## Dependencies

- T009, T013, T014

## In scope

1. `RunWorker` / orchestrator started when a run enters `running`.
2. Loop steps:
   - observe (Browser Use)
   - redact + checkpoint hooks (checkpoint write may call T018 if present; else skip large payload)
   - Jev decide
   - audit decision (with alternatives/confidence)
   - execute action
   - audit action result
   - stop on `DONE`, terminal error, cancel, or approval pause (hooks for T020/T021)
3. Structured error handling with retries where Browser Use already provides them; don’t infinite-loop.
4. Concurrency: one worker task per run; global cap configurable.
5. Integration test with fake Jev + mocked browser observation/action (no need for real Chrome in CI unit tests).

## Out of scope

- Text LLM writing (T016) — for `TYPE_TEXT`, either stub text from goal or fail closed until T016
- Approval policy details (T021) — provide a `needs_approval(action)` hook returning False by default
- UI

## Acceptance criteria

- [ ] A run with fake Jev reaches `DONE` and leaves a coherent event chain
- [ ] Every decision and action attempt has audit events
- [ ] Cancellation cooperative check exists between steps
- [ ] Secrets do not appear in stored payloads (redaction path used)

## Suggested files

```text
src/<package>/agent/loop.py
src/<package>/agent/worker.py
tests/test_agent_loop.py
```

## Implementation notes for the model

- Prefer explicit step_ids.
- Keep the loop readable over cleverness; this will be the most debugged file in the repo.
