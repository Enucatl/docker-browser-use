# T016 — Small text LLM gate for `TYPE_TEXT` only

## Goal

Call a small generative model only when free-form text must be written into the page; Jev still chooses *that* typing is needed and *which* field.

## Context

Jev selects `TYPE_TEXT` + target; the text LLM proposes the string (invoice month, search query, etc.). Do not use the text LLM for click targeting.

## Dependencies

- T015

## In scope

1. `TextLLMClient` interface + one real provider adapter (OpenAI-compatible or whatever the homelab already uses — check `shared-inference` if relevant, but do not over-couple).
2. Prompt includes: goal, field context (redacted), nearby labels, constraints; excludes secrets.
3. Audit full model request/response via model-call tracing (coordinate with T017; write events even if T017 tables are minimal).
4. Config for model name, base URL, API key via `*_FILE`.
5. Tests with fake client.

## Out of scope

- Using the text LLM for general planning
- Streaming tokens to UI (optional nicety, not required)

## Acceptance criteria

- [ ] Non-`TYPE_TEXT` actions never call the text LLM
- [ ] Prompts are redacted
- [ ] Failures surface as run errors or retries with audit events

## Suggested files

```text
src/<package>/policy/text_llm.py
tests/test_text_llm_gate.py
```

## Implementation notes for the model

- Prefer `niquests` for HTTP.
- Keep max tokens small; this is form-filling, not essays.
