# T019 — Screenshot policy (WebP/JPEG, event-driven capture)

## Goal

Capture screenshots as artifacts on important transitions without storing lossless PNGs on every action or enabling continuous video.

## Context

Prefer WebP or JPEG for routine shots. Capture on: important transitions, errors, approvals, destructive actions, and periodic heartbeats — not blindly every step. Video remains off by default.

## Dependencies

- T007, T015

## In scope

1. Screenshot capturer via Browser Use / CDP.
2. Encode WebP/JPEG with quality settings in config.
3. Policy hooks aligned with checkpoint moments where sensible.
4. Artifact metadata + event references.
5. Tests with a fake image bytes path (don’t require real Chrome in unit tests).

## Out of scope

- Continuous video
- Public image CDN
- HAR capture (optional later)

## Acceptance criteria

- [x] Screenshots stored via artifact store with hashes
- [x] Default policy does not screenshot every action
- [x] Config can tighten/loosen capture frequency

## Suggested files

```text
src/<package>/audit/screenshots.py
tests/test_screenshots_policy.py
```

## Implementation notes for the model

- Never put screenshot binaries in Postgres.
- Consider stripping EXIF if any.
