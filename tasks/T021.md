# T021 — Human approval gates for high-impact actions

## Goal

Block high-impact actions until an authenticated human explicitly approves or rejects them in the UI/API.

## Context

High-impact examples: purchases, financial submissions, destructive actions, account changes, sending consequential messages. Pattern: agent fills the form; human approves the irreversible step.

## Dependencies

- T011, T015, T020

## In scope

1. `needs_approval(action, context) -> ApprovalRequest | None` with a conservative default allowlist/blocklist.
2. When approval needed: set run status `awaiting_approval`, emit event, push WS message, wait.
3. API: approve / reject with user identity from T012.
4. Persist `human_approvals` rows (decision, reason, timestamp, user).
5. On reject: fail run or ask Jev to replan — pick one documented behavior.
6. Tests for approve and reject paths.

## Out of scope

- Full policy engine richness (T028)
- Bitwarden-specific unlock prompts (T027/T023)

## Acceptance criteria

- [ ] Configured high-impact action cannot execute without approval
- [ ] Approver identity recorded
- [ ] Timeout behavior documented (fail closed recommended)

## Suggested files

```text
src/<package>/agent/approvals.py
src/<package>/api/routes/approvals.py
tests/test_approvals.py
```

## Implementation notes for the model

- Never auto-approve in production defaults.
- Include human-readable reason strings for the UI.
