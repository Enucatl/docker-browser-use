# T022 — Live agent Chrome view (Xvfb + noVNC) behind Traefik/Authelia

## Goal

Let the operator watch the agent’s real Chrome from desktop Firefox via noVNC, without exposing CDP.

## Context

First implementation: Xvfb + VNC/noVNC. CDP remains internal. The VNC UI may be:

- a path on `browser-use.${DOCKER_DOMAIN}` (e.g. `/vnc`) with stripprefix, or
- a separate host like `browser-use-vnc.${DOCKER_DOMAIN}`

Both must use `authelia@docker,secured@file` and join `traefik_proxy` only for the noVNC HTTP service — not for the raw VNC port.

Reference path-prefix pattern: `/opt/docker/paperless-ai/docker-compose.yml`.

## Dependencies

- T004, T013, T012

## In scope

1. Run Chrome headed against Xvfb in the browser container (or sidecar).
2. x11vnc (or equivalent) + noVNC web assets.
3. Traefik labels for the noVNC HTTP port with Authelia + secured middlewares.
4. Document that this is operator viewership; mutual control details are T023.
5. Ensure filesystem/hardening still sane (`limits-*` likely); document exceptions.
6. Manual test notes: login via Authelia, see the X session.

## Out of scope

- Efficient WebRTC streaming replacement
- Exposing CDP
- Full take-control mutex (T023)

## Acceptance criteria

- [x] Operator can open the Authelia-gated noVNC page and see Chrome
- [x] CDP/VNC binary ports are not publicly published
- [x] Traefik middleware chain includes Authelia

Implementation: headed Chromium on Xvfb + internal x11vnc (`browser`); Authelia-gated
`novnc` at `/vnc/` (paperless-ai PathPrefix + stripprefix). Docs: `docs/live-view.md`.
View-only until T023. Manual Authelia browser login may need a human on the LAN.

## Suggested files

```text
docker-compose.yml  # novnc service or ports on browser
Dockerfile.browser  # packages
docs/live-view.md
```

## Implementation notes for the model

- Prefer separate `novnc` service networking to browser via internal net if that simplifies hardening.
- Do not put noVNC on the internet without Authelia + allowlist (`secured@file`).
