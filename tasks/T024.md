# T024 — Minimal Agent Web UI (run, watch, pause, approve, history)

## Goal

Ship a private Web UI for giving instructions, watching progress, pausing/resuming, approving actions, opening live view/takeover, and browsing run history.

## Context

Operators use desktop Firefox → `https://browser-use.${DOCKER_DOMAIN}`. The UI talks to the FastAPI/WS backend. Keep the first version functional and plain; this is a control panel, not a marketing site. Prefer a simple server-rendered or light SPA approach consistent with maintainer skills — do not overbuild.

## Dependencies

- T011, T012, T020, T021 (T022/T023 link optional but desirable)

## In scope

1. Pages/views:
   - New run (goal textarea + start)
   - Active run (live events, current decision, status, cost placeholder)
   - Controls: pause/resume/cancel
   - Approval prompt UI
   - History list + run detail
   - Links to live view / take control when available
2. Static assets served by the controller or a minimal front-end build.
3. Use Authelia session (no local password DB).
4. Basic responsive layout that works on phone for approvals.
5. Smoke tests for HTML routes or component tests as practical.

## Out of scope

- Pixel-perfect design system
- Multi-tenant SaaS features
- Cost charts (T029)

## Acceptance criteria

- [x] Authenticated user can start a run and see WS updates
- [x] Approve/reject and pause/resume work from UI
- [x] History shows prior runs from Postgres
- [x] UI is only reachable via Traefik+Authelia path

## Suggested files

```text
src/<package>/web/   # templates/static or frontend/
tests/test_web_ui.py
```

## Implementation notes for the model

- Favor boring, readable UI code.
- Do not embed CDP directly in the browser client.
