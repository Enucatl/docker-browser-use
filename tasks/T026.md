# T026 — Install Bitwarden into the persistent Chrome profile

## Goal

Provision the Bitwarden browser extension into the agent Chrome profile volume so later tasks can invoke autofill actions without teaching secrets to Jev.

## Context

Extensions live in the persistent profile. Prefer scripted/ reproducible install where possible; if Chrome policy/extension sideload is required in the image, document it.

## Dependencies

- T013

## In scope

1. Decide install method (baked into image vs first-boot script vs managed policy).
2. Ensure extension survives browser container recreation (profile volume).
3. Document operator steps for vault account login / unlock (human takeover expected).
4. Confirm extension does not break headless/headed CDP automation (smoke).
5. Note TOTP/passkey limitations.

## Out of scope

- Jev Bitwarden actions (T027)
- Syncing the operator’s personal desktop Bitwarden profile blindly

## Acceptance criteria

- [ ] Bitwarden extension present in the agent profile after setup
- [ ] Documented unlock path via takeover
- [ ] No vault credentials stored in git or ordinary env files

## Suggested files

```text
docs/bitwarden-setup.md
scripts/provision_bitwarden_extension.sh  # if applicable
Dockerfile.browser  # if baked in
```

## Implementation notes for the model

- Prefer an agent-specific Bitwarden account/vault collection with least privilege.
