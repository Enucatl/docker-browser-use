# T027 — Explicit Bitwarden actions (`LOGIN` / `IDENTITY` / `CARD`)

## Goal

Implement specialized agent actions that trigger Bitwarden autofill rather than asking models for secrets.

## Context

Jev may select `BITWARDEN_LOGIN`, `BITWARDEN_IDENTITY`, or `BITWARDEN_CARD`. Bitwarden performs the fill. Audit records success/failure and harmless identifiers (e.g. `****4242`) — never password/CVV/PAN/session material. Redaction (T008) is mandatory.

## Dependencies

- T015, T026, T008

## In scope

1. Action executors that drive the Bitwarden extension UI via Browser Use carefully, or use a supported extension automation approach — document reliability risks.
2. Map action parameters to “which item” without exposing secrets (item name/id heuristics).
3. Audit events: fill requested, fields affected (names only), result.
4. Approval hooks for card/payment fills (should usually require T021).
5. Tests with mocked extension interactions.

## Out of scope

- Storing vault unlock password in the agent controller
- Teaching Jev the password

## Acceptance criteria

- [ ] Happy-path login fill works on a test page in manual smoke
- [ ] Secrets absent from Postgres events and model traces
- [ ] Card fill defaults to requiring approval

## Suggested files

```text
src/<package>/browser/bitwarden_actions.py
tests/test_bitwarden_actions.py
```

## Implementation notes for the model

- If extension automation is brittle, implement a narrow MVP (login only) and leave identity/card stubs with clear TODOs.
