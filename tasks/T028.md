# T028 — Richer approval policy engine (rules + UI reasons)

## Goal

Replace the Phase 1 hard-coded approval heuristics with a configurable policy engine that explains why approval is required.

## Dependencies

- T021

## In scope

1. Policy rules as config (YAML/TOML) versioned in repo, e.g. match action type, URL regex, element text, confidence below threshold.
2. Each block produces a stable `reason_code` + human message for UI.
3. Hot reload optional; restart reload is fine.
4. Tests covering rule precedence and default-deny for money keywords.

## Out of scope

- ML-based risk scoring

## Acceptance criteria

- [ ] Policies are data-driven, not only Python if-statements
- [ ] UI shows the reason string from the policy
- [ ] Unit tests for rule evaluation without browser

## Suggested files

```text
src/<package>/agent/policy_engine.py
config/approval_policies.yaml
tests/test_policy_engine.py
```

## Implementation notes for the model

- Keep evaluation pure and fast; called every step.
