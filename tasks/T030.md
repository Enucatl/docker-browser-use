# T030 — OpenTelemetry instrumentation alongside Postgres audit

## Goal

Add operational OpenTelemetry traces/metrics for the observe → decide → act loop while keeping PostgreSQL as the semantic forensic record.

## Context

OTel is for latency/errors in Grafana/Tempo later. Homelab may already have OTLP ingress patterns (see Traefik mTLS OTLP notes in sibling stacks); start with configurable OTLP export endpoint and safe defaults (off or local).

## Dependencies

- T015

## In scope

1. Instrument run worker spans: observe, jev, text_llm, execute, approve_wait.
2. Propagate `run_id` / `step_id` as attributes.
3. Metrics: step latency, queue depth, approval wait time.
4. Document how this differs from `agent_events`.
5. Tests that spans are created with a console/inmemory exporter.

## Out of scope

- Replacing Postgres audit
- Standing up Grafana/Tempo in this repo (link to existing `grafana-loki` if relevant)

## Acceptance criteria

- [ ] Traces can be exported when OTLP endpoint configured
- [ ] Default compose does not require Tempo to start the stack
- [ ] No secrets in span attributes

## Suggested files

```text
src/<package>/telemetry/otel.py
tests/test_otel_spans.py
```
