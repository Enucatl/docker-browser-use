# T031 — Multi-profile support (Personal / Work / Testing)

## Goal

Support multiple persistent Chrome profiles selectable per run.

## Dependencies

- T013, T024

## In scope

1. Profile registry (id, display name, filesystem path, notes).
2. API + UI profile picker on run create.
3. Concurrent runs: define whether profiles are exclusive (recommended: lock profile while in use).
4. Audit which profile was used.
5. Compose volumes or subdirectories for each profile.

## Out of scope

- Syncing with desktop Firefox profiles
- Per-profile Bitwarden accounts automation beyond docs

## Acceptance criteria

- [ ] Two profiles can exist with isolated cookies
- [ ] UI can select profile
- [ ] In-use profile cannot be started by a second run (or behavior clearly documented)

## Suggested files

```text
src/<package>/browser/profiles.py  # extend
src/<package>/api/routes/profiles.py
tests/test_profiles.py
```

## Implementation notes for the model

- Keep Testing profile as the default for smoke tests.
