# T032 — Offline Jev evaluation harness from recorded states

## Goal

Replay recorded browser-state checkpoints into Jev version A vs B without revisiting live sites, for regression and cost/quality comparison.

## Context

Historical runs become the evaluation dataset because candidate action spaces were retained (T018).

## Dependencies

- T014, T018

## In scope

1. CLI: `evaluate-jev --run-id ... --checkpoint ... --client A/B`.
2. Load compressed checkpoint, rebuild Jev request, capture decision + confidence.
3. Compare to historical decision; emit a small report (JSON/Markdown).
4. Fixture-based unit test with a recorded sample payload in `tests/fixtures/`.

## Out of scope

- Live website crawling for eval
- Automatic production model swap

## Acceptance criteria

- [ ] Can evaluate at least one fixture checkpoint offline
- [ ] Report includes selected action, confidence, and match/mismatch vs original
- [ ] No network required for fixture test

## Suggested files

```text
src/<package>/eval/jev_replay.py
tests/fixtures/sample_checkpoint.json.zst
tests/test_jev_replay.py
```

## Implementation notes for the model

- Version the checkpoint schema; reject unknown versions loudly.
