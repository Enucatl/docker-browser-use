# T035 — Periodic signed audit checkpoints

## Goal

Extend hash chaining with periodic signed checkpoints so historical modification is detectable even if an attacker rewrites a contiguous event range and recomputes hashes.

## Context

T009 provides per-run hash chains. This task adds signed checkpoint records (ed25519 or similar) over chain heads at intervals / run end.

## Dependencies

- T009

## In scope

1. Key management via Docker secret (private key) + mounted public key for verify.
2. `audit_checkpoints` table: run_id, seq, chain_hash, signature, created_at.
3. Writer creates checkpoint every N events and on run terminal states.
4. Verification CLI that validates chain + signatures.
5. Tests with generated ephemeral keys.

## Out of scope

- HSM/KMS integration
- Public transparency log

## Acceptance criteria

- [ ] Tampering that rewrites hashes without signature key fails verify
- [ ] Keys never committed to git
- [ ] Checkpointing overhead documented as negligible

## Suggested files

```text
src/<package>/audit/signed_checkpoints.py
tests/test_signed_checkpoints.py
secrets/audit_signing_key  # local only
```

## Implementation notes for the model

- Prefer ed25519 via the Python stdlib/cryptography library already acceptable to the project.
- Rotate keys by adding new kid; keep old public keys for verify.
